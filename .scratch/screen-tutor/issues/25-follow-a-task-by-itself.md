# 25: Follow a task across pages by itself

**What to build:** in a cloud console one click changes the page, and the marks drawn for the old page stay behind; and the learner had to type a message after every click. Now the app watches the screen: when the page changes the old marks go at once, and when it has settled the tutor looks at the new page and gives the next step (or says the learner went the wrong way, or that the task is done) without a message.

**Blocked by:** 22, 23, 24.

**Status:** built; tried with the live model on the mock console and in Chrome (the web playground simulates the click); the watching itself is unit tested and the screen capture checked in Electron, but not yet seen by the owner on a real screen.

How the reference project does it (read from its source by a research sub-agent, 2026-10-04): Pointr is a Chrome extension, so it reads the page itself: a click listener, a URL poller, a check that the target is still on the page and visible, a mutation observer that settles after quiet; a new step replaces the old overlay; an automatic loop (observe, think, wait for the action, settle, observe again) with a cap of 40 turns, goal and history kept per tab, a predicted-next-step fast path, and a check-in after three off-path clicks. Clicky (macOS) only clears the pointer on the next hotkey or after a short timer and asks again for every step. We cannot read other apps, so we read pixels instead; the loop is the same.

- [x] The tutor states a `goal` for a task and repeats it on later turns; `progress` says how it is going: continue, off_track, waiting (nothing to say yet: no steps at all) or done. The request carries the goal and a `trigger` (a message, or the screen having changed).
- [x] The screen is read as a video stream (about 15 pictures a second) in a hidden window (follow/watcher.ts, 640 by 360, hidden windows are not in it). A still capture of the whole screen takes about 0.6 s, which made the first version slow (1 to 2 s before the old marks went); the stream notices a changed page in about 0.1 s (measured in Electron: marks stale after 87 to 143 ms).
- [x] ChangeDetector (follow/changeDetector.ts, 19 tests): pictures are averaged down 4 by 4 first (flicker on single pixels, which the capture produces at the edges of text, disappears; real text stays). Stale when more than 4 percent of the picture differs from the screen the marks were drawn for. Fire when a change has settled: 0.7 s of stillness after a page change, 1 s after a small one. Small changes count: a few typed letters make cells pile up in one block. The detector only looks for movement where the change is, ignores a box around the mouse pointer (position sent from the main process), parts of the screen that never stop moving (a playing video, a spinner) until they are still, and the taskbar (the clock). Measured in Electron: typing a name fires after about 1.2 s, a page change fires after about 0.8 s.
- [x] On a fire, if following is on and the app is not busy, an automatic turn is sent with the new capture, the conversation and the goal; the chat shows a quiet line ("The screen changed. Checking what comes next") instead of a message from the learner. Caps: 25 automatic turns per goal; three off-track answers in a row pause following and say so; a silent "waiting" answer adds nothing to the chat.
- [x] If the learner acted while an answer was still being written, the change is noticed against the screen the answer was started on.
- [x] The chat shows the goal and a "Following your clicks" switch (pause and resume); done ends the task; New chat forgets it.
- [x] Live model on the mock console: goal kept, next step each time, "off_track" when the learner ended up on the dashboard again, a new form walked field by field.
- [x] Ways to stop a task: the Following switch (pause), End task button and Ctrl+Shift+S (end it, cancel what is being fetched, take the marks off), the Stop button (cancels the answer and pauses following), New chat, and an idle pause after 15 minutes. Checked end to end with a fake backend: after End task a new page change sends nothing.
- [x] The watcher starts again once if its stream does not come up within 5 seconds, and logs ready, stale and fire.
- [ ] Not done: a predicted-next-step fast path (Pointr points within about half a second while the model call runs); noticing a click on the pointed spot (we only see the result on screen); no automatic offer of help when the learner stays stuck for a while.
- [ ] To check on a real screen: that scrolling is treated as a change (marks cleared) and that a page that keeps animating does not fire again and again (the motion test waits for stillness).
